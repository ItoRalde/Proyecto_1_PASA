================================================================================
CODE STRUCTURE SUMMARY: restructured_implementation/
================================================================================

Overview:
---------
A clean, minimal, modular implementation of the 5-dimensional Dual-PPG + 3-Axis
Accelerometer Heart Signal Reconstruction and Separate LMS Hyperparameter
Optimization Pipeline. Preprocessing and BPM detection are kept strictly minimal
so that the MISO LMS adaptive filter is the core motion-cancellation mechanism.

Directory Structure:
--------------------
restructured_implementation/
├── __init__.py
├── dataset_preparation.py
├── preprocessing.py
├── reference_construction.py
├── LMS_algorithms.py
├── fusion.py
├── bpm_detection.py
├── pipeline.py
├── optimization.py
├── pipeline_optimization_and_evaluation.ipynb
└── code_structure_summary.txt

Module Breakdown:
-----------------
1. dataset_preparation.py
   - `load_ts(path)`: Loads 5D windows `(n_windows, 5, 1000)` and BPM labels `y`.
   - `split_participants(X)` & `get_participant_groups(X)`: Detects recording
     session / participant boundaries via 750-sample overlap matching without
     merging windows.
   - `subject_wise_group_kfold(X, n_splits=5)`: Partitions windows strictly by
     subject ID using `sklearn.model_selection.GroupKFold` to prevent data leakage.

2. preprocessing.py
   - `bandpass(x, lo=0.5, hi=4.0, fs=125, order=4, causal=False)`: 4th-order
     zero-phase Butterworth bandpass filter in the cardiac band (30 - 240 BPM).
   - `normalize_amplitude(x)`: Zero-mean, unit-variance normalization per channel.
   - `preprocess_signal(x)`: Minimal preprocessing returning `(ppg1, ppg2, acc)`
     where `acc` has shape `(3, N)` (`[accx, accy, accz]`).

3. reference_construction.py
   - `build_U(acc, M)`: Constructs the `(N, 3 * M)` MISO tapped-delay regressor
     matrix for $\hat{m}[n] = \sum_{k=1}^3 \mathbf{w}_k^T[n]\mathbf{a}_k[n]$.

4. LMS_algorithms.py
   - `standard_lms(d, acc, M, mu)`: Standard MISO LMS filter.
   - `nlms(d, acc, M, mu, delta)`: Normalized MISO LMS filter.
   - `vs_lms(d, acc, M, mu_max, mu_min, alpha, gamma, delta)`: Kwong-Johnston
     Variable Step-Size MISO LMS filter.
   - `lms_bucket(ppg1, ppg2, acc, algorithm, M, **hyperparams)`: Runs the selected
     LMS variant in parallel on `ppg1` and `ppg2` and fuses `e1` and `e2` via
     `snr_weighted_late_fusion`.

5. fusion.py
   - `estimate_cardiac_snr(sig)`: In-band cardiac spectral SNR in `[0.5, 4.0] Hz`.
   - `compute_snr_weights(e1, e2)` & `snr_weighted_late_fusion(e1, e2)`: Combines
     parallel-filtered PPG channels using SNR weights $w_i = \text{SNR}_i / (\text{SNR}_1 + \text{SNR}_2)$.

6. bpm_detection.py
   - `zero_padded_periodogram_bpm(x, fs=125, nfft=8192, lo=0.5, hi=4.0, window_type='hann')`:
     Direct zero-padded periodogram peak detector in `[0.5, 4.0] Hz`.
   - `elgendi_systolic_peak_bpm(x, fs=125, w1_sec, w2_sec, beta_offset)`:
     Time-domain systolic peak heart rate detector.
   - `estimate_bpm_window(e_window, hr_algorithm, **hr_params)`: HR bucket function.
   - `objective_function(bpm_estimated, bpm_true)`: Outlier-penalized error metric.

7. pipeline.py
   - `reconstruct_heart_signal(window_5d, ...)`: End-to-end window signal cleaning.
   - `predict_window_bpm(window_5d, ...)`: End-to-end single-window BPM prediction.
   - `HeartRateEstimatorModel`: Encapsulates a configured LMS + HR pipeline with
     `.predict(X)` and `.predict_with_signals(X)`.

8. optimization.py
   - `optimize_hr_pipeline(X, y, n_splits=5, ...)`: Evaluates `standard_lms`,
     `nlms`, and `vs_lms` separately using Subject-Wise Group K-Fold CV and
     2-phase Conditional TPE optimization with `MedianFoldPruner`, plus evaluates
     the Before-LMS baseline (`evaluate_baseline_without_lms`).

9. pipeline_optimization_and_evaluation.ipynb
   - Presents the pipeline, outputs the selected hyperparameters and CV/Test
     performance for each of the 3 LMS types vs. the Before-LMS baseline, plots
     the spread of Test BPMs colored by subject, visualizes a single window
     changing across each pipeline step, and compares the raw vs. cleaned signal
     of a good example and an outlier example.
